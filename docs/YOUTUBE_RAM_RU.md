# YouTube съедает всю оперативную память — что делать

Короткий ответ: вкладка YouTube в браузере — самый «прожорливый» способ
смотреть видео. Один ролик в 1080p спокойно занимает **1–2 ГБ**, а 4K/AV1 на
слабом процессоре — **до 3–4 ГБ**, потому что браузер держит отдельный процесс
под вкладку, отдельные процессы под рекламу/трекеры и кэш уже декодированных
кадров. Ниже — что делать, от самого эффективного шага к косметике.

---

## 0. Сначала выясните, кто именно ест память

Без этого любые советы — пальцем в небо.

1. `Ctrl+Shift+Esc` → Диспетчер задач → вкладка **Производительность** →
   «Память». Посмотрите «Используется» и «Доступно».
2. В самом браузере нажмите **Shift+Esc** (Chrome/Edge — «Диспетчер задач
   браузера», Firefox — `about:processes`). Там видно, сколько памяти берёт
   каждая вкладка и каждое расширение.
3. Закройте вкладку YouTube и посмотрите, вернулась ли память. Если память *не
   возвращается* даже после закрытия браузера — проблема не в YouTube
   (см. раздел 6).

Ориентир для ПК с 8 ГБ: браузер с одной вкладкой YouTube — 1.5–3 ГБ,
свободно должно оставаться хотя бы 1–1.5 ГБ. Если «Доступно» падает до 100–200
МБ и начинаются фризы — вы в свопе, отсюда и ощущение «перегружает всё».

---

## 1. Смотреть YouTube вообще без браузера (самый большой выигрыш)

В этом репозитории есть скрипт `youtube_lite.py`: он отдаёт ссылку в **mpv**
(лёгкий плеер), поток вытаскивает **yt-dlp**. Никакой рекламы, скриптов,
аналитики и фоновых вкладок.

| Способ | Память на одно видео 1080p |
|---|---|
| Chrome, одна вкладка YouTube | 1 200 – 2 500 МБ |
| Chrome + ещё 5 вкладок | 2 500 – 4 000 МБ |
| `youtube_lite.py` (mpv, 720p) | 150 – 350 МБ |
| `youtube_lite.py --audio` (музыка) | 80 – 150 МБ |

Установка (Windows, PowerShell):

```powershell
winget install yt-dlp
winget install mpv
winget install Gyan.FFmpeg      # нужен для склейки видео+звук в HD
```

Проверка и запуск:

```powershell
python youtube_lite.py --check                 # что установлено
python youtube_lite.py https://youtu.be/XXXX   # смотреть
python youtube_lite.py "lofi hip hop"          # поиск и первое совпадение
python youtube_lite.py URL --quality low       # 360p — минимум памяти
python youtube_lite.py URL --audio             # только звук
python youtube_lite.py --gui                   # маленькое окно-пульт
```

Почему это работает: у mpv буфер ограничен (`--demuxer-max-bytes=96MiB`), нет
многопроцессной архитектуры, нет рекламы, и он умеет аппаратное декодирование
(`--hwdec=auto-safe`). Смотреть 4K на 8 ГБ всё равно не стоит — ставьте 720p.

---

## 2. Если браузер нужен — оптимизируйте его

По убыванию эффекта:

1. **Уберите софтдекод VP9/AV1.** Установите расширение **h264ify** (или
   «Enhanced h264ify») — YouTube начнёт отдавать H.264, который декодирует
   видеокарта. На старых CPU это разница в 1–3 ГБ памяти и заметный минус
   нагрузки на процессор. Минус: 4K в H.264 недоступно (максимум 1080p).
2. **Блокировщик рекламы.** uBlock Origin (или AdGuard) убирает видеорекламу —
   а это отдельные процессы и отдельный буфер на каждый рекламный вставка.
3. **Выключите «Ambient mode»** (подсветка-градиент вокруг плеера): настройки
   YouTube → шестерёнка в плеере → «Дополнительные настройки» → Ambient mode →
   выкл. Это постоянный рендер размытого фона во весь экран.
4. **Отключите автовоспроизведение и превью при наведении** — каждое превью
   подгружает отдельный видеопоток.
5. **Не держите YouTube в фоне.** Вкладка на паузе всё равно держит кэш;
   «спящие вкладки» спасают не всегда.
6. **Ограничьте качество до 720p** (шестерёнка → Качество). 4K на мониторе
   1080p не даёт ничего, кроме нагрузки.
7. **Проверьте аппаратное ускорение.** Chrome/Edge: Настройки → Система →
   «Использовать аппаратное ускорение» — должно быть **включено**. Если при
   включённом видео дёргается и драйвер старый — наоборот, выключите и сравните.
8. **Включите экономию памяти.** Chrome: Настройки → Производительность →
   «Экономия памяти». Edge: Настройки → Система → «Спящие вкладки» + «Режим
   эффективности».
9. **Выгрузите расширения.** Каждое расширение — свой процесс. 15 расширений
   легко дают +500 МБ.
10. **Отдельный профиль/окно только для видео** с одним расширением (h264ify) и
    без остальных вкладок.

Продвинутый вариант — запускать браузер с ограничением числа процессов
(ярлык → Свойства → Объект):

```
chrome.exe --renderer-process-limit=4 --process-per-site
```

Это снижает накладные расходы на процессы, но повышает шанс, что падение одной
вкладки потянет за собой другие. Если не уверены — не трогайте.

## 3. Настройки Windows, которые помогают

- **Файл подкачки** должен быть не «0 МБ»: Система → Дополнительные параметры
  системы → Дополнительно → Быстродействие → Виртуальная память. Поставьте
  «Автоматически» или вручную 4096–8192 МБ. Без подкачки при нехватке RAM
  приложения просто закрываются.
- **Схема электропитания** — «Сбалансированная» или «Высокая
  производительность» (в «Экономии энергии» память не виновата, но фризы
  усиливаются).
- **Автозагрузка**: Диспетчер задач → Автозагрузка — уберите всё, что вам не
  нужно при старте (Steam, Discord, лаунчеры, «оптимизаторы»). 8 ГБ кончаются
  именно из-за фонового зоопарка.
- **Не используйте «чистильщики памяти»** (Memory Cleaner и подобные). Они
  вытесняют полезный кэш, после чего система начинает читать всё с диска —
  становится только хуже.

---

## 4. Сколько памяти вообще нужно

- **8 ГБ** — сегодня это минимум: Windows 11 + браузер с 3–5 вкладками уже
  упираются в потолок. YouTube в 1080p+ здесь всегда будет впритык; смотрите
  через mpv в 720p.
- **16 ГБ** — комфортно для браузера с YouTube и десятком вкладок.
- **32 ГБ** — нужны только для монтажа/виртуалок/локальных LLM.

Если в ПК две планки по 4 ГБ — можно добавить ещё две (проверьте, что есть
свободные слоты и поддержку двухканального режима). Это единственное настоящее
«лечение» нехватки памяти.

---

## 5. Проверка результата

1. Запишите «Используется» до изменений (Диспетчер задач → Память).
2. Откройте одно и то же видео тем же способом.
3. Смотрите `Shift+Esc` в браузере (или Диспетчер задач) на конкретный процесс
   вкладки.
4. Сравните. Хороший результат после h264ify + uBlock на слабом CPU — минус
   30–50% памяти вкладки; переход на `youtube_lite.py` — минус 70–85%.

---

## 6. Если память утекает без YouTube

Симптомы: память не освобождается после закрытия браузера, растёт сама по себе,
вентиляторы шумят в простое.

- Диспетчер задач → сортировка по памяти → найдите процесс-«пылесос».
  Часто это антивирус-«оптимизатор», RGB-софт, лаунчер или повреждённое
  расширение.
- Проверьте систему на майнер/вирус (Microsoft Defender — полная проверка,
  плюс бесплатный Malwarebytes для второго мнения). Майнер, спрятанный в
  браузере, выглядит именно как «YouTube съел всю память».
- Обновите драйвер видеокарты: старый драйвер течёт памятью при аппаратном
  декодировании.
- Если память в Диспетчере задач растёт без запущенных программ и бывают
  синие экраны — проверьте планки памяти MemTest86 (загрузочная флешка,
  минимум 2 прохода).
- Windows может показывать «высокую занятость» из-за кэша — это нормально.
  Смотрите на «Доступно», а не на «В кэше».
